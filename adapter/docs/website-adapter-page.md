## 区块 1 · 为什么是「管家」，而不是又一个聊天框

- **它是调度器，不是工人**：管家本身不敲代码，而是听懂你要在哪个项目做什么，
  把复杂任务派给 worker 子代理跑完整 agentic 流程，全程盯进展。
- **为对讲机而生**：1.47" 小屏 + PTT 按键 + 语音播报。回答天然简短、可朗读——
  先给结论，不甩大段代码。你不在电脑前也能推进工作。
- **形态借鉴 OpenClaw**：编排者 + 本地工作空间的思路，落到硬件语音外设上。

## 区块 2 · 工作原理（配一张流程图）

> 前端用现有插画/线框呈现下面这条链路：

```
你说话 → ASR → 管家会话（加载本地人设+记忆）
      → dispatch 派给某个项目里的 worker → 结果 → TTS 语音播报回你
```

三个关键词，给三个小卡片：

1. **本地工作空间**：`~/.bbclaw-adapter/workspace/` 里装着管家的人设
   （`CLAUDE.md`）与按维度分文件的长期记忆（`MEMORY/`）。
2. **项目白名单**：只有你授权的工程目录能被派活，安全可控。
3. **长期记忆**：用户偏好、在做的项目、关键决策会跨会话、跨设备沉淀，
   并带抗投毒过滤。

## 区块 4 · 第一次对话，它自己认识你（产品亮点）

强调**零表单、纯对话**的初始化体验：

> 第一次跟管家说话，它会先把你的请求办了，再顺势问几句——
> 「我该怎么称呼你？」「你的角色 / 职业是？」「现在主要在忙什么？」
> 你随口回答，它就记进身份档案，之后一直用这个称呼叫你、按你的角色调整默认做法。
> 不想答？一句「以后再说」它就不再追问。

配一段对话气泡示意：

```
你   ：帮我看看这个项目最近的提交
管家 ：最近三条都是 UI 改造…对了，我该怎么称呼你？
你   ：叫我老周，我是项目负责人
管家 ：好的老周，以后默认按负责人视角给你结论。
```

要点 bullet：
- onboarding 永远让位于你当下的请求，绝不打断紧急任务
- 身份由管家手写维护，不会被自动提炼的笔记覆盖
